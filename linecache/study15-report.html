Four findings, consistent across every codebase and cross-checked by the definition-plane probes. (1) Holistic cold-strict compressibility is an entropy floor set by the codebase (102–2131×). (2) The S0 semantic-Root memo makes the repeated-build basis (the production reality: a persistent per-daemon dictionary) clear 400× on every codebase, 3706–41102×. (3) Throughput is airtight: a real two-process socketpair sustains ≥1 GB/s single-stream, byte-exact. (4) Even the definition plane alone, source-conditioned (toolchain headers free, since icecream ships the environment), clears 400× on 14 of 15 — DuckDB is the single holdout (269×), because 89% of its dictionary is its own project code. Cold-400× is a property of how much unique code a codebase ships.

2   Holistic cold FinalRatio — a codebase entropy floor

Log scale. Same-scale codebases differ >10× (Eigen vs DuckDB, both ~650 TUs): the spread is the codebase, not the corpus size. No method (LZ z3..z19, LDM, front-code, skeleton-columnar, PPM/MTF, cross-project pretraining, trained zstd dict, source-conditioned COPY-programs) lifts the capped ones to a holistic 400×.

3   S0 amortized (40 builds) — ≥400x everywhere

Repeated-build basis: build 0 ships the dictionary cold; unchanged TUs in later builds are a 56-byte ROOT_REF. Every codebase clears 400× by 9–100× — this is where the win lives.

4   The definition plane: own-source fraction vs source-conditioned ratio

Why only DuckDB stays capped. x = fraction of the dictionary that is project code (must ship); y = source-conditioned dict-leg ratio (toolchain lines free). Strong anticorrelation: the more of its own code a codebase ships, the lower its ceiling. DuckDB (89% own-source) is the sole point under 400× (269×); every other — apps and libraries alike — clears it once toolchain headers are free. (This is the dict leg only; the holistic cold in panel 2 is additionally bounded by the per-TU structure legs.)

5   Cross-project coverage saturates fast — and low for apps

defcodec's leave-one-out learning curves: each codebase's line coverage from a prior built of the k largest OTHER projects. Apps plateau near 5% (own code is unique — a bigger prior barely helps); libraries saturate at 40–75% (mostly shared system headers). Curves flatten by k≈3–9: cross-project transfer is real but bounded and quickly exhausted.
