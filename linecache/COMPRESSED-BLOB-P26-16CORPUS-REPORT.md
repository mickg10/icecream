# P26 compressed embedded blobs: exact 16-corpus execution

## Result

P26 is a measured cold factor on top of M1 direct generation-local ordinals. It detects complete
zlib streams represented as generated C/C++ byte arrays and selects, independently for each TU,
between:

1. the inflated members concatenated and encoded as one zstd-3/LDM frame; and
2. the untouched original DEFLATE bytes.

F reconstructs every selected member, validates its exact original length and 128-bit digest, and
requests only members that did not reproduce. All accounting below includes complete Roots,
Blocks, definitions, cache dialogue, paths, blob frames, recovery traffic, and framing.

All 48 complete executions reconstruct every byte of all 9,292 TUs:

| complete 16-corpus state | same-machine M1 direct | P26 | saving | P26 ratio | target result | minimum pipeline |
|---|---:|---:|---:|---:|---:|---:|
| cold | 108,370,164 | **97,021,934** | **11,348,230** | **294.31x** | 25,635,255 B over 400x | **1.110 GB/s** |
| cache bit 0 | 76,520,160 | **65,181,646** | **11,338,514** | **438.08x** | 77,591,712 B under 200x | **1.266 GB/s** |
| cache bit 1 | 43,884,473 | **43,876,139** | **8,334** | **650.80x** | 98,897,219 B under 200x | **2.843 GB/s** |

The measured cold saving exceeds the ruled 8 MB continuation threshold. P26 does not close
cold-400: the next independent cold contender must still remove **25,635,255 bytes**. Both
aggregate half-cold states remain comfortably over 200x. Godot's byte-skewed bit-0 state is still
the only individual half below 200x, at 172.76x.

## Executed codec

```text
C                                                                    F

generated BYTE_ARRAY values
        |
        +--> discover complete zlib members
        |      {array extent, deflated size, inflated size, digest}
        |
        +--> inflate once
        |      |
        |      `--> concatenate per TU --> zstd-3 + LDM ----+
        |                                                    |
        `--> concatenate untouched original members --------+-- choose smaller
                                                             |   complete frame
                                                             v
                                                      TU blob descriptor
                                                      + selected payload
                                                             |
                                                             +--------------->
                                                                            |
                                             +------------------------------+
                                             |
                                  ordinary?  |  transformed?
                                      |      |       |
                                      |      |       +--> zstd decode
                                      |      |       +--> canonical zlib-9
                                      |      |       +--> validate size/digest
                                      |      |
                                      +------+--> exact members?
                                                    |
                                              no ---+----> NEED(member ordinals)
                                                    |               |
                                                    |    C sends only original
                                                    |    bytes for named members
                                                    v
                                          splice byte-array values
                                                    |
                                          render exact original .ii
```

The wire mode is explicit in the array-control frame:

- mode 1: transformed payload plus eager exact patches;
- mode 2: transformed payload plus member-only recovery when required;
- mode 3: untouched original DEFLATE bytes.

Each descriptor names its first array entry, entry count, original size, inflated size, and exact
digest. The canonical codec identity is serialized as `zlib-1.2.11-level9`. Mode 3 is not
zstd-compressed a second time: the original member bytes are already compressed, and sending them
raw removes wasted CPU while making the losing path trivial to decode.

The selector charges actual framed bytes. For the transformed candidate it includes its zstd
frame, optional patch frame, and patch metadata. For the ordinary candidate it includes the raw
member bytes and frame. The winning mode is chosen per TU, so a locally losing transform cannot
penalize the rest of the corpus.

All naturally selected level-9 members reproduced exactly, so the complete 48-run matrix needed

Only Godot contains selected members. On the same `quietbox2` source environment, every wire

saving is attributable to the blob factor rather than to an unrelated codec change.

## Eager patch versus member-only recovery

The exact eager row recompresses each blob on C so C can calculate an initial patch, then performs
the same canonical recompression on F. It is exact but fails the throughput requirement:

| full Godot, Zen 4 | wire | canonical exact / corrected | C encode | F decode | pipeline |
|---|---:|---:|---:|---:|---:|
| eager level-9 patch | 44,731,122 | 112 / 0 | 0.710 | 1.245 | **0.710 GB/s** |
| member-only recovery, repeat 1 | 44,731,020 | checked on F | 1.095 | 1.231 | **1.095 GB/s** |
| member-only recovery, repeat 2 | 44,731,020 | checked on F | 1.109 | 1.238 | **1.109 GB/s** |
| member-only recovery, repeat 3 | 44,731,020 | checked on F | 1.099 | 1.234 | **1.099 GB/s** |
| final-source confirmation | 44,731,020 | checked on F | 1.107 | 1.243 | **1.107 GB/s** |

The eager path adds only 102 wire bytes when all members reproduce, but duplicate canonical work
reduces C throughput by about 35%. The measured product recommendation is therefore mode 2 with
exact member validation and member-only recovery. This is a simple F-generated `NEED` extension,
not a second cache or predictor.

Two focused controls cover the losing branches:

- Canonical level 8 produces 37 exact and 71 corrected members. The selector chooses untouched
  original bytes in three of four TUs and reconstructs the full input exactly.
- Forced recovery every 17th member requests four ordinals in 19 bytes and returns 155,181 framed
  bytes. The complete output remains exact.

The initial transformed choice cannot know whether F's canonical bytes will match. If recovery
occurs, those reply bytes are charged to the actual complete wire. Once F has already received the
transformed frame, requesting only failed members is the minimum incremental correction; sending
the whole ordinary candidate would be strictly larger for that TU.

## Why the zstd frame is per TU

The standalone four-TU control contains 108 members, 29,453,332 original bytes, and 114,071,960
inflated bytes. Every strategy below decodes and verifies the full expanded payload:

| expanded-payload strategy | zstd level | payload wire | metadata | charged wire |
|---|---:|---:|---:|---:|
| one frame for all four TUs | 1 | 21,054,931 | 606 | 21,055,537 |
| independent frame per TU | 1 | 21,038,580 | 606 | 21,039,186 |
| one frame for all four TUs | 3 | 18,151,844 | 606 | 18,152,450 |
| **independent frame per TU** | **3** | **18,150,442** | **606** | **18,151,048** |
| persistent stream with TU flushes | 3 | 18,142,024 | 606 | 18,142,630 |
| independent frame per member | 3 | 27,696,641 | 606 | 27,697,247 |

Persistent TU flushes save only 8,418 bytes over independent TU frames, while coupling later TUs
to earlier stream state. Per-member framing loses 9.55 MB. Independent zstd-3/LDM TU frames are
therefore the smallest simple independently decodable choice, and the integrated payload
(18,150,458 bytes including its frame accounting) agrees with the standalone measurement.

## Validation

- Warning-clean release builds of the integrated codec and standalone stage benchmark.
- Cold, bit-0, and bit-1 matrices reconstruct all 9,292 TUs exactly: 48/48 corpus runs.
- All seven wire categories and every mixed/blob subcategory close each per-corpus total.
- Same-machine M1 and P26 inputs, environment, compiler flags, affinity, and manifests match.
- Every zero-blob corpus has identical direct and P26 wire in all three states.
- Four retained full-Godot executions exceed 1 GB/s on the 16-core Zen 4 host; the fourth uses
  the final source after the empty-member boundary correction.
- ASan+UBSan executes one 102.6 MB TU, 11 selected members, and three forced recoveries exactly.
- A synthetic TU with twenty empty zlib members selects the transformed zero-byte payload and
  reconstructs exactly, covering the zero-inflated-size boundary.
- Sixteen focused learning/property tests pass; Python compilation, Ruff, deterministic summary
  regeneration, both older parser regressions, and `git diff --check` pass.

The capability harness retains the whole corpus and dictionary for analysis, reaching 7.48 GiB
peak RSS on Godot. That is not the proposed product lifetime: product framing is per TU, while the
bounded object caches have their own eviction policy.

```sh
g++ -O3 -march=native -std=c++17 -DICE_LINE_CAP_LOG2=23 \
  -Wall -Wextra -Werror linecache/codec50.cpp \
  -lzstd -lz -pthread -o /tmp/codec50-p26
```

Run one state:

```sh
/tmp/codec50-p26 --manifest MANIFEST --z 3 \
  --mixed-regions --byte-array-lines --direct-ordinals \
  --compressed-blobs --blob-threads 8 --blob-lazy-fallback
```
