1 · Cold → hot learning

x-axis is TUs observed (prequential), continuing across repeated build loops. Dashed verticals mark phase boundaries (cold → warm loops → header-edit loops → revert). Primary metric is full charged wire (roots + newly-required Line/Block definitions + fills + framing, charged to the F that receives them). The warm loops replay the identical tree, so with a pure count-gate the learner keeps promoting deeper blocks each rebuild toward a degenerate ~1-token-per-TU floor; the informative signal is the slope (each identical rebuild roughly halves the root tokens) and the fact that it surpasses the single-build batch reference by loop ~2 (Q>1) by accumulating cross-build structure a one-shot batch never sees.

Effective compression: bits per input byte (full charged wire)

Cold loop pays first-time Line-text closure transfer; warm loops drop toward the steady floor. Per-TU MA128 shown faint.

Prequential predictor quality Q = (B−O)/(B−A)

B = marker-region baseline root code length (no blocks); O = online root code length using blocks published before the TU; A = retrospective batch region-BPE ceiling. 0 = no superblock benefit yet; 1 = batch reference. Unclamped: Q>1 means repeated online learning surpasses this batch reference.

Structure learning: root tokens per input region

How many top-level tokens the current predictor needs to cover one input region. Lower = more structure absorbed into blocks.

2 · Learner-state growth

Published immutable blocks vs TUs observed

Final: 98122 published, 44734 ever used, 53388 never used (max depth 25). Never-used blocks cost C-side predictor memory only — they are never sent to any F.

3 · Per-F definition multiplication

Definitions are charged once per F that actually receives them (closure-only, no global pre-send). Scattering one build across F caches (round-robin) means no single F is warm, so the cold Line-text closure is re-sent per F; sticky/affinity (return a build's TUs to the F holding its C_GUID) keeps it 1×.

Cold-build definition transfer vs F count

round-robin multiplies ~×F; sticky stays at the single-F cost.

4 · Promotion-gate sweep

Warm covering vs promote threshold

Lower promote gate = closer to the batch covering but more blocks (and, on high-diversity corpora, more never-reused Zipfian-tail blocks). A full-cost gate replaces the raw count gate in the product design.

Method & provenance

  • Observed vs modeled: root/def/missing byte counts and block/region/line structure are observed exactly (byte-exact: every TU's root tokens expand to its exact line-id stream, FNV-1a anchored to raw source). zstd sizes are observed per-TU (root, L3) and via a per-kind global ratio for definition closures (modeled). Framing is a fixed per-frame model (12 B root + 12 B fill).
  • Command: superblock-online-bench --manifest corpus/manifest.txt --promote 4 --sweep --curves curve-llvm --max-loops 20
  • Deferred panels (flagged, not yet plotted): LZ/phrase-trie alternative learner behind the same block store; full order-sensitivity matrix (reverse / scheduler-completion-order / fresh-shuffle-per-loop with seed bands); exact-DP covering control.
