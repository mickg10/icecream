Online superblock learning curves

Issue #16 line-dedup transport. The superblock layer is a continuously-growing online predictor over stable marker-region IDs: each TU is encoded with the predictor state learned from previously observed TUs only (prequential), the full per-F wire is charged, then the TU is learned from and newly-worthwhile region/block pairs are promoted into new immutable Block IDs (existing IDs never rebind) available to later TUs. Passes: COLD → WARM loops (identical rebuilds) → one high-fanout header-edit → REVERT. Every plotted point is auditable in the committed per-TU/per-loop TSVs; wire is byte-exact (root tokens expand to the exact line-id stream).

2 · Learner-state growth & generation pruning

Published immutable blocks vs TUs observed

Published blocks grow to 187560 across all loops. Under the raw count-gate most late promotions are never reused (C-side predictor memory only — never sent to any F); a full-cost gate bounds this. In a separate 4-pass run the used set held ~44734 of 98122 — see §4.

Generation pruning: at the warm plateau 174305 blocks are published but only 5073 are resident (referenced within the last build); 58977 (34%) were never reused — dropping those reclaims ~2.2 MiB of C-side predictor memory (def bytes 346 KiB) at zero wire cost. Generation rotation bounds the resident set to the actively-used blocks instead of the unbounded published total.

Generation pruning: published vs resident block set

Published grows unbounded on identical rebuilds; the resident set (blocks referenced within the last build window) and the never-reused count show what generation rotation reclaims. This — with the root-memo in §4 — is one of the two real memory bounds (the per-pair gate in §5 is not).

3 · Per-F definition multiplication

Cold-build definition transfer vs F count

Charged once per F that receives it (closure-only). Round-robin multiplies ~×F (no single F is warm); sticky/affinity stays 1×.

4 · Define-and-use whole-TU root memoization

On first sight of a TU, its whole root-token vector is labelled a root object (the child vector already crosses the wire, so the definition costs only a header); an identical later TU collapses to ONE ROOT_REF. It authorizes reuse only on exact object-sequence equality. Frozen deployed-dictionary result: an unchanged rebuild goes from 2 to 1.0 root tokens/TU (≈1 ROOT_REF), cutting full wire 1.8× (16 B/TU). On post-edit REVERT the old roots are instantly reusable (1.8× smaller with memo).

Full charged wire: stack-greedy vs +root-memo

During active learning the predictor churns the tokenization, so identical TUs rarely repeat their exact root vector and memo barely helps. In the FROZEN phase (deployed steady dictionary, learning off) an unchanged rebuild collapses to ~1 ROOT_REF/TU, and the post-edit REVERT is instantly reusable — the big memo/​no-memo gaps at the right.

5 · Promotion gate: count vs full-cost

Warm covering vs promote threshold (count gate)

Count-gate sweep: lower gate = closer covering but more blocks, and on high-diversity corpora a large never-reused Zipfian tail.

Blocks vs covering: count sweep vs full-cost rent-or-buy

Full-cost gate (publish a pair only when accrued foregone root-token savings ≥ def-bytes × per-F fan-out) BOUNDS the block count sharply, but on this data it does NOT dominate the count-gate frontier — a tuned count threshold reaches similar covering at similar block counts. Honest read: the per-pair gate shifts the operating point; the decisive memory bounds are generation pruning + the root-memo above, not a cleverer per-pair rule.

Method & provenance

  • Observed vs modeled: root/def/missing byte counts and block/region/line structure are observed exactly; zstd sizes are observed per-TU (root, L3) and modeled via a per-kind global ratio for definition closures; framing is a fixed per-frame model (12 B root + 12 B fill).
  • Prequential rule: a TU is scored with blocks published before it; only after scoring is it learned from — so new knowledge from a TU never improves its own point. x continues across all loops.
  • Regenerate: superblock-online-bench --manifest <corpus>/manifest.txt --promote 4 --sweep --curves <prefix> --max-loops 20 then python3 make_online_report.py --add Name:prefix:log ... --out superblock-online-report.html
  • Covering control (min-wire): for each sample TU we produce candidate parses — stack-greedy LEFT-to-right (the deployed encoder) vs RIGHT-to-left — actually zstd each root stream and keep the smaller (bigoracle's k-best-with-real-zstd). Both parses are byte-exact. Result: RL is far worse (LLVM 270,442 vs 2,462 tokens) because the grammar is LR-learned, so best-of-candidates = LR within ~0.03%. The greedy LR encoder is self-consistent with its co-learned grammar; there is no free wire for a smarter covering to recover. An exact-DP min-token optimum over the full recursive block grammar is intractable at scale (deep whole-TU blocks blow up the CYK/trie), which is why k-best-with-real-zstd is the practical control.
  • Independently cross-validated (separate agent, committed f6c18c9): order-sensitivity (≤0.46% wire spread across original/reverse/shuffled → order-invariant with a frozen store) and the pair-promotion-vs-LZ/phrase-trie comparison (pair-promotion uses 13–20× fewer blocks at equal-or-better wire).
