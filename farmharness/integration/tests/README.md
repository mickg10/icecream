# Local integration harness tests

These tests exercise the Python integration harness locally. They do not
connect to a farm, run Docker, or execute an integration suite against remote
workers. The test suite uses the Python version in `.python-version`, locked
pytest dependencies, and otherwise Python's standard library. Install uv
0.9.21; Make runs `uv sync --locked` automatically. Do not install pytest into
the host Python. The
suite also uses GNU Make, Git, Bash, a C++ compiler, Java, and common POSIX
utilities; Linux namespace tests skip when the host does not permit user/PID
namespaces. Java must be on PATH because the formal-runner unit tests exercise
its dependency preflight, even when their lane uses a small synthetic fixture.
These tests do not execute the full TLC matrix or require the real TLC jar.
The [Docker QA guide](../../../dev/README.md) describes the separate native
build dependencies supplied by the SDK. Run from the source tree:

```sh
ICEFARM_TMPDIR=/scratch/icefarm make test-harness-fast
ICEFARM_TMPDIR=/scratch/icefarm make test-harness-thorough
```

`ICEFARM_TMPDIR` is required for farm integration, harness, and formal Make
targets. Provision an existing writable absolute directory before invoking
them; the Make guard checks it without creating it. The setting is exported as
`TMPDIR`, `TMP`, `TEMP`, and `TEMPDIR` for child processes, and disables Python
bytecode writes. Provision it first, for example: `mkdir -p /scratch/icefarm`.

This routes Python downloads, uv caches/environments and harness temporary
files. It does not relocate the
Docker daemon's `DockerRootDir` or native compilation object files. For large
native builds, use an out-of-tree build directory on the desired storage.
The fast target skips tests marked `thorough`. The thorough target runs the
complete test directory, including the slower scale and namespace revalidation
checks. A previous complete run took 540.19 seconds, of which the retained
namespace revalidation test took 450.915 seconds; time varies with the machine.
Some retained-corpus probes depend on local external data and skip when those
files are unavailable; they do not make the rest of the test suite dependent
on a farm or Docker.
The historical H3 patch-application probe also skips in gitless source
snapshots when its exact base commit is absent; in a full Git checkout it
continues to verify that the patch applies to the unchanged historical files.

For individual tests use `sh dev/python.sh -m pytest
farmharness/integration/tests/PATH.py`. Use `make python-sync` for setup alone.
Both Make test targets avoid pytest's cache and Python bytecode writes.
Set `UV_OFFLINE=1` after preparation to require cached inputs and forbid
downloads. The lock is never regenerated by a test invocation.

## P51 external receipt-gate tool bundle

The opt-in `p51-receipt-window` farm workload needs `iptables` only inside its
disposable C test container. It does not modify the product image or the host.
To prepare the offline bundle, use an empty mounted scratch directory inside
the scenario's Debian 12 amd64 client environment (`ice-ii/debian-gcc:v2-p50`,
with the scenario's recorded image identity). Run these commands there, not
on a farm host:

```sh
apt-get update
export LC_ALL=C
apt-get download \
  iptables=1.8.9-2 libip6tc2=1.8.9-2 libmnl0=1.0.4-3 \
  libnetfilter-conntrack3=1.0.9-3 libnfnetlink0=1.0.2-2 \
  libnftnl11=1.2.4-2 libxtables12=1.8.9-2 netbase=6.4
sha256sum *.deb > SHA256SUMS
sha256sum -c SHA256SUMS
echo 'd1d7980ebc0b342caea791cc4fc86be4a6dcfc44f89e6884f2e4fbc69fd5568a  SHA256SUMS' | sha256sum -c -
```

Keep the eight `.deb` files and `SHA256SUMS` in one private directory, then set
`ICEFARM_P51_IPTABLES_BUNDLE` to that directory when invoking the farm workload.
The harness checks the complete manifest against its pinned digest, stages the
files to the disposable C container in bounded chunks, verifies the staged
hashes, and installs offline. Do not install these packages on farm hosts or
change the immutable product image for this test dependency.
